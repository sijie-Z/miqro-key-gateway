# MiQroGate 与腾讯 / 阿里云 AI 网关对比

> 更新：2026-08-29。对比对象：腾讯云 AI 网关（TSE，[文档](https://cloud.tencent.com/document/product/1826)）、阿里云 AI 网关（Higress 内核，[文档](https://help.aliyun.com/zh/api-gateway/ai-gateway/)）。吸收记录见 [tencent-ai-gateway-mapping.md](tencent-ai-gateway-mapping.md)。

## 一句话定位

| 产品 | 定位 |
|---|---|
| 腾讯云 AI 网关 | **多模型流量治理平台**：统一接入 20+ 供应商，智能路由、限流、缓存、脱敏，卖「治理能力」 |
| 阿里云 AI 网关（Higress） | **AI 原生 API 网关**：协议转换 + 多供应商代理 + Fallback + 插件体系，卖「接入与迁移能力」（主打 Claude Code 迁移） |
| **MiQroGate** | **凭证与额度的账本**：把一个真实上游 Key 安全地映射为多个可追踪、可轮换、可吊销的 Virtual Key，卖「治理的确定性」 |

核心差异一句话：**腾讯和阿里是「帮你在多家模型之间做智能选择」，MiQroGate 是「帮你把每一笔流量对应到固定的凭证、项目和额度上」**。

## 架构与部署形态

| 维度 | 腾讯 TSE | 阿里云 Higress | MiQroGate |
|---|---|---|---|
| 内核 | 自研 TSE 微服务平台 | 开源 Higress（Istio + Envoy，CNCF Sandbox） | 自研 Spring WebFlux / Reactor Netty |
| 部署 | 云上多可用区集群（VPC/节点/LB 全托管） | 云上集群（或计算巢私有化） | **单客户私有化**（Docker Compose，客户自持） |
| 规模目标 | 企业级多租户 | 企业级多租户 | 单租户 50 账号 / 50 并发流 |
| 扩展 | 弹性扩缩容、多可用区 | 同左 + 多集群 | 单节点，客户侧水平扩展（无自动扩缩承诺） |
| 依赖 | 腾讯云全家桶 | Redis、SLS、dashvector 等 | PostgreSQL + JDK 21（零中间件） |

## 功能维度对比

| 功能 | 腾讯 TSE | 阿里云 Higress | MiQroGate | 备注 |
|---|---|---|---|---|
| **模型接入** | 20+ 供应商内置 | 20+ 供应商内置（百炼/DeepSeek/OpenAI/Anthropic…） | 8 家供应商 23 个产品（签名目录，Ed25519 校验） | 数量我们少，但目录签名防篡改是独有 |
| **凭证管理** | 模型密钥（控制台配置） | API Key（建议 KMS 引用） | **上游凭证全生命周期**：AES-256-GCM 加密落库、轮换原子、宽限期、版本历史、指纹比对验证 | 凭证治理是我们的核心，两家的密钥只是「配置项」 |
| **客户端身份** | 消费者 + 消费者组 API Key | 消费者 + API Key | 用户 + 项目 + Grants，**Virtual Key 固定 1:1 绑定**（用户/项目/产品/凭证/用途） | 我们不做「一个 Key 访问多模型」的聚合 |
| **路由策略** | 6 种（模型名/权重/意图/参数/标签/延迟） | 5 种（单模型/模型名通配/权重/观测指标/智能语义） | **固定 1:1，无智能路由**（产品锁定决策） | 刻意差异：不负载均衡、不跨供应商 |
| **降级/Fallback** | 触发条件多选 + 备用服务按序 | Fallback 按序兜底 | **不自动故障切换**（首字节前最多安全重试一次） | 刻意差异 |
| **限流** | QPM + Token 限流 | Token 限流降级 | **不限流**（只做 Webhook 告警） | 刻意差异：单租户私有化无需租户级限流 |
| **响应缓存** | L1 Redis + L2 向量库（键=最新用户消息） | Redis + 向量库（键=GJSON 提取消息 content） | **L1 Caffeine + PostgreSQL**（键=请求哈希，ADR-0009）；默认双重 opt-in | 我们更保守：默认不缓存、不引 Redis、字节重放 |
| **内容安全** | 数据脱敏（日志/转发） | 内容审核插件 + 脱敏 | **不碰正文**（不落库/不进日志/不解读） | 设计差异：用「不保存」代替「脱敏」 |
| **协议转换** | 内置（OpenAI/Anthropic 等） | 内置（含 HTTP↔MCP） | **透明代理**，协议转换交给 CC Switch | 边界差异（产品决策） |
| **MCP** | MCP 服务管理 + Tools | MCP 管理（代理/HTTP 转 MCP） | 无（CC Switch 职责） | 刻意差异 |
| **用量统计** | 全链路 Tokens 观测 | Tokens 消费观测 + 计费 | **分级用量**（输入/输出/缓存 Token 分列）+ 成本分摊（按单价快照） | 我们的记账更细：价格快照不可变，历史成本不重算 |
| **成本管理** | 模型单价 + 命中统计 + 节省报表 | 观测指标 + 缓存命中率 | **单价目录 + 成本分摊 + 成本报表 + 缓存节省卡 + CSV 导出** | G7.2/G7.3 落地 |
| **可观测性** | 控制台指标 | SLS 日志/追踪（可记正文） | Prometheus + JSON 日志 + Grafana + 告警；**无正文日志**（隐私测试锁死） | 差异：我们默认无正文，合规负担最小 |
| **审计** | 操作日志 | 操作日志 | **哈希链审计**（内容篡改可检测）+ 全操作审计事件 | 独有能力 |
| **安全** | 网关级 WAF/DDoS 集成 | 内容审核 | SSRF 双门控 + 凭证加密 + Key 摘要存储 + 目录签名 | 私有化安全纵深 |

## 设计哲学差异（为什么不同）

1. **我们不做「智能」**：腾讯的意图识别路由、阿里的智能路由/观测指标路由都依赖对请求的语义理解——**必须读正文**。MiQroGate 的「不碰正文」决策排除了这些能力，换来的是隐私确定性。
2. **我们不做「聚合」**：两家的核心价值是「一个入口接所有模型」，MiQroGate 的「1:1 固定绑定」反其道而行——每个 Key 是谁的、花哪个产品的钱、走哪个真实凭证，**审计上无可辩驳**。
3. **我们做「账本」**：价格快照不可变、成本分摊可重算、额度按 5h/周/月窗口滚动——成本故事比两家的「观测指标」更接近财务语义。
4. **我们的部署约束反过来塑造了功能**：单客户私有化 → 不需要租户限流、不需要多可用区、不需要注册中心接入；离线部署 → 本地 SVG 图标、无 CDN 依赖、零中间件。

## 借鉴与不采纳清单

**已借鉴并落地**：
- 模型密钥管理 → G7.1 上游凭证门户
- 模型单价配置 → G7.2 定价目录
- L1 精确缓存方案 → G7.4（ADR-0009），本土化为 PostgreSQL + 内存
- 成本报表/命中统计 → G7.3 成本报表页 + 缓存节省卡
- 命名与信息架构 → TDesign（腾讯设计体系）+ 浅色密集操作台

**记录为优化项**：
- 缓存键从「全请求哈希」升级为「提取最后一条 user 消息」（腾讯与阿里一致的做法，多轮对话命中率更高）
- 网关部署信息页（对应腾讯「查看网关详情」）

**刻意不采纳（与产品锁定决策冲突）**：
- 智能路由 6 策略 / 5 种路由模式
- 降级 Fallback / 自动故障切换
- QPM / Token 限流
- 语义缓存（向量库依赖）
- 参数改写（透明代理不得改写请求 JSON）
- MCP / 协议转换（CC Switch 职责）
- 内容审核 / 正文日志（不碰正文）

## 结论

- **腾讯/阿里适合**：多模型供应商并存、需要弹性与智能调度的云上企业。
- **MiQroGate 适合**：单客户私有化、需要「每笔流量可审计、每分钱可对账」的确定性治理场景——尤其是把公司内部的 AI 编码流量（Claude Code / Codex 等经 CC Switch）纳入统一凭证与额度管控。

## 补充：阿里云侧新情报（2026-09-06 研究，对照百炼/Token Plan/AI 网关 FinOps 与 Higress）

> 素材：百炼 Token Plan 概述（alibabacloud.com/help/model-studio/token-plan-overview）、百炼限流（help/model-studio/rate-limit）、阿里云 API 网关 AI 网关发布记录（help.aliyun.com/zh/api-gateway/ai-gateway）、Higress AI Gateway 官方（higress.cn/ai-gateway 与 higress.io/en/ai-gateway）及社区综述。只做研究对照，未改产品决策。

**对使用方有直接价值的运营事实（写入 runbook 候选）**：
1. **Key 区域绑定与多形态端点**：百炼按量 `sk-*` Key 与 Coding/Token Plan `sk-sp-*` Key 走不同 Base URL；Key 区域绑定，跨区域调用报 InvalidApiKey。**订阅 Key 若透传到网关走按量 URL 会静默按量扣费且订阅看板零消耗**——CC Switch/网关配置文档应提醒用户区分（我们已按产品目录锁定端点，但上游 Key 类型误配仍可能发生，凭证指纹校验与 400/401 归因已在验证流程内）。
2. **用量可见性 T+1**：百炼「模型监控」调用统计约一小时后可见——与我们的本地即时记账形成对账窗口差异；对账/水位的「官方值滞后」在文档中已有口径，此点可强化备注。
3. **429/403 语义**：RPM/TPM 超限 → 429（一分钟内自恢复）；免费额度用完（用完即停）→ 403。与网关上游错误归因文档兼容。

**功能形态对照（映射/不采纳）**：
| 阿里云形态 | 我们对应/裁决 |
|---|---|
| AI 网关 FinOps：消费者 Token/Credits 配额，周期=日/周/月/年 + 自定义 + 时区 + 水位监控；消费者组 + API 授权；模型资产 Credits 配额管控 | 对应我们配额规则（USER/PROJECT 作用域、TOKENS/REQUESTS、DAILY/WEEKLY/MONTHLY、水位+告警不阻断）。**不采纳**：Credits 归一化单位（跨供应商换算引入估算语义）、年/自定义周期（内部 50 账号无此需求）、消费者组（无组实体）、配额硬阻断（锁定决策：只告警） |
| Higress 语义缓存（Embedding+向量库，宣称省 40-60%） | 与 ADR-0009 方向一致但**刻意不采纳向量库形态**（零中间件 + 不引正文特征化）；我们语义键=末条 user 消息哈希（腾讯/阿里精确缓存同源思路的轻量版） |
| Higress 多 Key 均衡/Key 池轮询 | **刻意不采纳**（1:1 固定绑定；Key 池轮询破坏审计映射） |
| Higress 模型 Fallback/降级链 | 刻意不采纳（不自动故障切换） |
| Higress MCP 托管/HTTP↔MCP 转换（唯一原生内置 MCP Server 的网关对比点） | MCP 代理按 ADR-0013 已落地（我们的范围=本网关出口的 MCP 服务代理与 ACL/韧性），HTTP-to-MCP 转换留给 CC Switch/平台侧 |
| Higress KMS 密钥集成、请求侧加密脱敏 | 对位=我们的 AES-256-GCM 信封加密 + ADR-0014 密文留痕（默认关）；KMS 集成不在私有化默认范围 |
| Higress Token 限流（Redis 令牌桶） | 刻意不采纳（不限流，只告警；零中间件） |
| 百炼不支持 OpenAI `GET /models`，需手动填模型 ID | 佐证我们 `/v1/models` 按 Virtual Key 授权返回模型的决策价值（真实消费者需要它） |

**结论增量**：三家把「治理能力」越做越厚的同时，我们差异化的三根支柱（不碰正文/1:1 绑定/只告警不阻断）依旧成立；阿里侧新增的观察点只有两个**运营提醒**（Key 形态误配扣费、官方用量 T+1），不构成功能立项。
